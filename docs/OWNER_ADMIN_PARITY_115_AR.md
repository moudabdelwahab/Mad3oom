# 115 — مالك المنصة داخل لوحة الإدارة

## السبب الجذري

منذ 038/040 السلطة ثلاثة محاور: **الهوية** (`profiles.role`، والمالك `platform_owner` دائمًا)، و**السلطة**
(`platform_authority`)، و**السياق** (`owner_context_state`). ودوال السلطة واعية بالسياق:

| المُسنَد | يمرّ لـ |
|---|---|
| `is_admin()` | رتبة `admin`، أو المالك في سياق `owner`/`admin` |
| `is_platform_staff()` | رتبة `admin`/`support`، أو المالك في سياق `owner`/`admin` |
| `has_elevated_authority()` | الأدمن المرتفع، أو المالك في سياق `owner` |

لكن 040 أعاد كتابة السياسات التي تسمّي `is_main_admin` وحدها. وبقي في ثلاث طبقات ما يفحص **الرتبة الحرفية**:

1. **قاعدة البيانات:** 46 سياسة على 36 جدولًا (منها `storage.objects`)، وأربع دوال، تفحص `profiles.role = 'admin'`
   أو `in ('admin','support')`. وأربع سياسات وأربعة مواضع في دالتين تفوّض بالبريد (`support@`).
2. **دوال Edge:** ثمانٍ تقرأ `profiles.role` بمفتاح الخدمة وتقارنه بـ`'admin'`.
3. **الواجهة:** صفحات الإدارة تقارن `profile.role === 'admin'` أو البريد لتقرر ما تعرضه.

فحين يدخل المالك لوحة الإدارة: الحارس (`guardPage`) يفتحها له لأنه يحترم السياق، ثم تُرسم الأقسام فارغة وتُرفض
العمليات. الإعدادات، الوسوم والردود الجاهزة، قاعدة المعرفة، حالة الخدمات، قائمة الانتظار، البريد، الأخطاء،
المنتدى، المكافآت والمحافظ، النطاقات الفرعية، الأتمتة، القوالب، رسائل التذاكر، الدخول كعضو.

## الإصلاح

القاعدة ① في 040 حرفيًا: **كل مُسنَد يُعاد بنفس نطاقه، ويُضاف إليه فرع المالك وحده مشروطًا بسياقه.**

| الطبقة | قبل | بعد |
|---|---|---|
| السياسات | `role = 'admin'` | `is_admin()` |
| السياسات | `role in ('admin','support')` | `is_platform_staff()` |
| السياسات | `role = 'admin' ∨ email = 'support@…'` | `is_admin()` (حساب support@ برتبة admin، فلا يفقد شيئًا) |
| المحفظة المركزية | بريد JWT = support@ | `can_manage_central_wallet()` = نفس الشرط ∨ المالك في سياق `owner` |
| الدوال | `approve/reject_reward_report`، `wf_is_admin` بالرتبة | `is_admin()` |
| الدوال | `get_service_report_summary` بالرتبتين | `is_platform_staff()` |
| Edge | `profile.role === 'admin'` | `callerHas('is_admin', …)` بجلسة المنادي |
| Edge | `['admin','support'].includes(role)` | `callerHas('is_platform_staff', …)` |
| الواجهة | `profile.role === 'admin'` / البريد | `platformAuthority()` — نفس المُسنَدات من القاعدة |

## ما بقي مقيّدًا عمدًا

- **المحفظة المركزية والأدمن الرئيسي:** مستوى السلطة المرتفعة (`owner_only`). في سياق الإدارة يرى المالك ما يراه
  الأدمن العادي، كما صمّمه 040.
- **منح الرتب وحظر الطاقم:** `owner_critical_ok()` (تحقق بخطوتين) — لم يتغير.
- **`_account_request_requester_ok`:** يستثني المالك عمدًا. الإداري يطلب والمالك يقرر.
- **الدوال التي تفحص رتبة الهدف لا المنادي:** أهلية الوكيل، حرّاس الرتب، توزيع إشعارات الأدمن. لم تُمسّ.
- **`mcp/_shared/actor.ts`:** هوية مفتاح API بلا جلسة ولا سياق. خارج نطاق هذا التغيير.
- **عزل الشركات (097+):** السياسات التقييدية فوق هذه الجداول كما هي. لا وصول جديد لبيانات الشركات.

## ترتيب النشر

وحدة واحدة، بهذا الترتيب:

1. `migrations/115_owner_admin_parity.sql`، ثم التحقق: `select public.can_manage_central_wallet();`
2. دوال Edge: `create-subdomain`، `manage-subdomain`، `check-dns-status`، `get-attachment-url`، `send-ticket-email`،
   `create-template`، `wf-executor`، `sie-channel-telegram` (كلها تستورد `_shared/caller-authority.js`).
3. الواجهة.

الواجهة قبل الترحيل آمنة: `platformAuthority` تعود لشرط البريد القديم للمحفظة المركزية إن غابت الدالة. والدوال
قبل الترحيل آمنة أيضًا، لأن `is_admin()` و`is_platform_staff()` موجودتان منذ 040.

**التراجع:** `migrations/_rollback/115_owner_admin_parity.down.sql` يعيد تعريفات الإنتاج حرفيًا (بصمة md5 مُختبَرة).
