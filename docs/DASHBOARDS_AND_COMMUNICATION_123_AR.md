### 2.4 الصلاحيات (RBAC) — ما رُوجع

- **فريق المنصة لا يرى محادثات الشركة مع عملائها** (102): مثبت مجددًا في 123 ③ (`AD`, `SUP`, `OW` بسياقه: `P0002`).
- **الأدمن المرتفع لا يرث سلطة المالك**: `elevated_admin` طالب في `admin_owner` لا مجيب، ولا يرى محادثات زملائه (123 ⑤).
- **المالك في سياق `company_admin`** يتكلم باسم شركته وحدها، ولا يرى نطاق المنصة ولا الداخلي (123 ④⑥).
- **الإخفاء في الواجهة ليس حماية**: الودجت يعرض ما يعيده `comm_overview()`، وكل نداء يعيد الخادم فيه حساب الجانب. اختبار العرض يثبت أن البوابة لا تعرض `admin_owner` حتى لو أعطاها الخادم (دفاع ثانٍ)، والـSQL يثبت أن الخادم لا يعطيها أصلًا.

## 3. محرّك التواصل الموحّد (Phase 2 + 5)

### 3.1 النطاقات

```
customer_company   عميل الشركة  ──►  فريق شركته           جداول 102 كما هي (لا نسخ ولا نقل)
company_platform   مدير الشركة  ──►  طاقم مدعوم           comm_threads(scope='company_platform', company_id NOT NULL)
admin_owner        طاقم المنصة  ──►  مالك المنصة          comm_threads(scope='admin_owner',      company_id IS NULL)
```

**لماذا لا تُنقل محادثات 102؟** 102 مطبَّق في الإنتاج ومفعّل (`company_inbox_enabled`)، بصلاحيات 098 وعزل 096/099 واختبارات. النقل = إعادة كتابة دوال تعمل. فالمحرّك **واجهة واحدة تفرّع على النطاق**: `customer_company` يمر عبر دوال 102 نفسها (هي الحارس)، والجديد فوقها المرفقات وربط التذكرة فقط. اختبار ⑧ يثبت أن دوال 102 لم تتغير حرفًا.

### 3.2 الحقول المطلوبة ↔ التنفيذ

| المطلوب | التنفيذ |
|---|---|
| `communication_scope` | `comm_threads.scope`، `comm_attachments.scope`، `comm_events.scope`، `comm_ticket_links.scope` |
| `sender_id` | `comm_messages.sender_id` (+ `sender_side`: requester/responder) |
| `recipient_id` | لا عمود: المستلم **دور لا شخص** (أي مالك، أي طاقم، مدير الشركة) ويُحسب في الخادم عند كل قراءة. عمود ثابت كان سيصير قديمًا عند تغيّر الطاقم |
| `company_id` | `comm_threads.company_id` — إلزامي لـcompany_platform، ممنوع للداخلي (CHECK)، ثابت (trigger) |
| `conversation_id` / `message_id` | `comm_threads.id` / `comm_messages.id` |
| `attachments` | `comm_attachments` + مستودع خاص `comm-attachments` |
| `read_status` | `comm_reads(thread_id, user_id, last_read_at)` + `unread` محسوب |
| `notifications` | `notifications` بنص عام بلا محتوى، ورابط `?comm=<scope>` يفتح الودجت |
| `timestamps` | `created_at`، `last_message_at`، `closed_at`، `comm_events` إلحاقي |
| `conversation_status` | `open`/`closed` + `priority` (normal/high/urgent) + `category` لكل نطاق |

### 3.3 الدوال (كلها `SECURITY DEFINER`، للـ`authenticated` وحده)

| الدالة | الغرض |
|---|---|
| `comm_overview()` | جانب المنادي في كل نطاق، المفتوح، غير المقروء، وتفعيل المرفقات |
| `comm_thread_start(scope, category, subject, body, key, priority, attachments)` | الطالب وحده؛ مفتاح منع تكرار؛ 5 في الساعة |
| `comm_threads_list(scope, filter, q)` | open/closed/all/mine/unassigned + بحث (حروف LIKE مُهرَّبة) |
| `comm_thread(scope, id)` | المحادثة + الرسائل + المرفقات + القدرات؛ يعلّمها مقروءة |
| `comm_post(scope, id, body, internal, attachments)` | الرد؛ الملاحظة الداخلية لطاقم المنصة في company_platform؛ رد الطالب يعيد فتح المغلقة؛ 30/5 دقائق |
| `comm_thread_assign` / `comm_thread_set_status` | الإسناد لطاقم المنصة؛ الإغلاق وإعادة الفتح |
| `comm_link_ticket(scope, id, ticket)` | ربط تذكرة أنشأها **الطالب نفسه** خلال ساعة (الإنشاء بالمسار المعتاد: الحصة والعزل كما هما)، وفي نطاق المحادثة نفسه كما ختمه 097: محادثة عميل ⇒ تذكرة `company` لشركتها هي؛ محادثة الشركة مع المنصة ⇒ تذكرة `mad3oom_support`. فلا يرى فريق شركة رقم تذكرة من شركة أخرى |
| `comm_attachment_begin(scope, id, name, mime, size)` | حجز مسار يختاره الخادم قبل الرفع |
| `comm_staff_directory()` | طاقم المنصة المؤهل للإسناد (للمجيب وحده) |

### 3.4 من هو «الطالب» ومن هو «المجيب»

| النطاق | الطالب | المجيب |
|---|---|---|
| customer_company | العميل صاحب المحادثة (102) | فريق الشركة بصلاحيات 098 (102) |
| company_platform | مدير الشركة الحالية (`company_staff_role() = 'admin'`، يحترم سياق المالك) | `is_platform_staff()`: admin/support، أو المالك في سياق owner/admin |
| admin_owner | صاحب المحادثة نفسه ما دام admin/support غير محظور، وليس المالك | `owner_capability('owner_only')`: المالك في سياق owner وحده |

قرارات مقصودة:
- **الشركة الموقوفة تستطيع مراسلة المنصة** (اختبار ④): هي أحوج ما تكون لذلك. الإيقاف (099) يبقى نافذًا على مراسلة عملائها.
- **مشرف الشركة وموظفها لا يراسلون المنصة باسم الشركة** — المدير وحده (أقل صلاحية). يمكن توسيعه بمفتاح في كتالوج 098 لاحقًا.
- **المالك لا يبدأ محادثة في admin_owner** — هو المجيب؛ يبدأ بالرد.

### 3.5 المرفقات

1. `comm_attachment_begin` يتحقق من صلاحية الكتابة في المحادثة، والنوع (قائمة مغلقة)، والحجم (10MB)، ويحجز `<scope>/<thread>/<uuid>`.
2. الرفع إلى `comm-attachments` — سياسة `INSERT` تقبل **المسار المحجوز لصاحبه وحده** خلال ساعة.
3. `comm_post(..., attachments)` يربط الحجوزات بالرسالة في نفس المعاملة: حجزي، نفس المحادثة، مرفوع فعلًا، مرة واحدة، 5 على الأكثر.
4. القراءة: سياسة `SELECT` تعيد فحص **الرسالة** في كل طلب — مرفق ملاحظة داخلية داخلي؛ مرفق محادثة عميل لا يراه طاقم المنصة.
5. المرفق المرسَل لا يُعدَّل ولا يُحذف (trigger).

## 4. بوابة عميل الشركة (Phase 3)

`/portal/` أصبحت تجربة مستقلة بأقسام: **تذاكري · رسائلي · الإشعارات · حسابي** (شريط ثابت أعلى الصفحة، روابط لأقسام الصفحة نفسها).

| الوظيفة المطلوبة | أين |
|---|---|
| تسجيل الدخول وإدارة الحساب، الملف الشخصي | «حسابي»: `mountAccountSettings` (الملف الشخصي، كلمة المرور، التحقق بخطوتين، الأجهزة) |
| إنشاء تذكرة، متابعتها، الرد عليها | «تذاكري» (كما كانت، `createTicketStream('portal')`) |
| المحادثات، المرفقات، سجل التواصل، التحويل إلى تذكرة | «رسائلي»: المحرّك مضمَّنًا |
| الإشعارات | «الإشعارات»: إشعاراته وحده (RLS)، تحديد الكل كمقروء، والضغط ينقل لقسم البوابة المناسب ولا يخرج العميل للوحة ليست له |
| منظور المالك (preview) | لا إشعارات ولا حساب ولا تواصل — قراءة لبيانات الشركة فقط |

| اللوحة | النطاقات المعروضة | موضع التركيب |
|---|---|---|

- قائمة، بحث، فلاتر، تبويب لكل نطاق، شارة غير المقروء، المحادثة، المرفقات، الإسناد، الملاحظة الداخلية، الإغلاق، التحويل إلى تذكرة.
- حالات التحميل (هياكل)، الفراغ، الخطأ مع «إعادة المحاولة»، ورسائل خطأ مفهومة بحسب رمز الخادم (`0A000`, `P0002`, `54000`, …).
- العربية/الإنجليزية تتبع `<html lang>` وتُعاد الرسم عند التبديل؛ `dir="auto"` للنصوص المختلطة.
- الوضع الداكن يتبع `data-theme` ثم تفضيل النظام؛ الأزرق لون أساسي.
- الهاتف: اللوحة بكامل الشاشة، أهداف لمس ≥ 44px، بلا تمرير أفقي.
- كل محتوى المستخدم يُكتب بـ`textContent` (اختبار يثبت أن `<img onerror>` يظهر نصًا ولا يُنفَّذ).
- الموضع يمين ثابت لأن ودجت الدردشة العامة (`chat-widget.js`) يسار ثابت في لوحة الإدارة.

## 8. التثبيت على الإنتاج

1. مراجعة `migrations/123_communication_engine.sql` ثم تطبيقه (`apply_migration`). يتطلب 102 (مطبَّق).
2. التحقق: `select key, enabled from platform_feature_switches where key like 'comm\_%'` ⇒ ثلاثة، مطفأة. ومستودع `comm-attachments` خاص.
3. **فور التطبيق** تتحول «رسائلي» في البوابة إلى المحرّك تلقائيًا (company_inbox_enabled مفعّل في الإنتاج) — نفس المحادثات والصلاحيات، مع البحث والتحويل إلى تذكرة. المرفقات تبقى مطفأة حتى الخطوة 5.
4. تفعيل النطاقين الجديدين من لوحة المالك (حوكمة ← المفاتيح، `owner_set_feature_switch` بتحقق خطوتين):
   `comm_company_platform_enabled`، `comm_admin_owner_enabled`.
5. تفعيل `comm_attachments_enabled` بعد التأكد من حدود المستودع (10MB والأنواع) في لوحة Storage.
6. التراجع: `migrations/_rollback/123_communication_engine.down.sql` — يرفض مع مفتاح مفعّل أو أي بيانات.
