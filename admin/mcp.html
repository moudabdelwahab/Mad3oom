مزوّدو الذكاء الاصطناعي والبوابات

هذه الصفحة لوحة إدارة فقط — لا تنادي أي مزوّد بنفسها. كل تشغيل حقيقي يمر عبر خدمة ai-gateway المستقلة، والمفاتيح تُشفَّر على الخادم ولا تُعرض كاملة أبدًا بعد الحفظ.

الموديلات وقدراتها

القائمة تُكتشف من كل مزوّد عبر "مزامنة الموديلات" ولا تُكتب يدويًا في النظام. القدرات المعروضة بجانب كل موديل تشرح لماذا تختاره — والموديل الذي يدعم البرمجة أو التفكير يفتح بيئة تطوير بدل صندوق شات عادي.

التوجيه وسلسلة الاحتياطي

حدّد أي موديل يخدم أي وضع — المحادثة البسيطة لموديل أرخص، والتفكير والبرمجة لموديل أقوى. عند فشل الأساسي ينتقل الـ Gateway تلقائيًا للاحتياطي التالي في نفس السلسلة، ويُسجَّل ذلك في الاستخدام.

الاستخدام والتكلفة

كل نداء يمر عبر الـ Gateway يُسجَّل بتوكناته وتكلفته وزمن استجابته — لكل مزوّد ولكل موديل على حدة، بما في ذلك المحاولات الفاشلة والتحوّل للاحتياطي.

بيئة التطوير (Coding Agent)

تعامل مع الموديل كوكيل تطوير لا كصندوق شات: أوضاع تشغيل مختلفة، جلسات محفوظة، وسجل لكل نداء. لا يوجد تنفيذ كود أو نظام ملفات حقيقي في المتصفح — نقاط الامتداد (sandbox • repository • github • filesystem • terminal • code execution) معرَّفة وجاهزة للتفعيل من الخادم لاحقًا.

إضافة خادم MCP جديد

يُشفَّران على الخادم قبل الحفظ. اتركهما فارغين عند التعديل للإبقاء على القيمة الحالية.
يُشفَّر على الخادم قبل الحفظ. اتركه فارغاً عند التعديل للإبقاء على القيمة الحالية.
يُشفَّر ككتلة واحدة على الخادم. يُدمج كـ headers وقت الاتصال الفعلي.
حالة الاتصال:
سجّل هذا الرابط كـ Authorized Redirect URI عند مزود الـ OAuth.
تُضاف فوق أي auth headers أعلاه، لأي احتياج إضافي.

قدرات الموديل

إضافة موديل يدويًا

استخدم هذا لو المزوّد لا يعرض قائمة موديلات، أو لو مفتاحك محصور في موديلات بعينها. القدرات هنا تُحفظ كـ "معدّلة يدويًا" فلا تدهسها أي مزامنة لاحقة.

انسخه كما هو من لوحة المزوّد — يُرسل حرفيًا في نداء الـ API.
